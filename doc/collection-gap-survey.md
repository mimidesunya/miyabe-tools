# 収集取りこぼしの現況と残っている課題

会議録・例規集の収集で起きる取りこぼし（取れていない、取れているのに読めていない、
別の中身を正しい名前で出している、取れているのに公開していない）について、
どんな型があり、何を直し、何が残っているかをまとめた文書である。2026-08-30 に
福岡県議会の議員連盟補助金を調べて、根拠の委員会記録も補助金交付規則も検索に
出てこなかったことから始まり、2026-10-01 の第72ラウンドまで調べて直してきた。
調べた経緯と個々の修正の中身は、ラウンドごとに
[collection-gap-survey-history.md](collection-gap-survey-history.md) に時系列で残してある。

括弧の「第N」は履歴の第Nラウンドの節を指す（第63・第64 と「第62 追記」は、
第62 の節の追記の中にある）。「1-3-6」「3 章 A」のような番号は第30ラウンドまでの
初期調査の章と節を、「」で囲んだ名前は履歴の節名を指す。不具合の型の分類と直す順序は
[collection-design-issues.md](collection-design-issues.md) にある。
状態は 2026-10-01 時点で、調査記録に書かれた範囲で判断した。第70（2026-09-06）の
あとの修正には、この記録に書かれていないものがある。記録と食い違うと git log で
分かったものは、その旨を書いた。記録だけでは決められないものは「要確認」に分けた。

## 取りこぼしの型

| 型 | 中身 | 主な例 |
| --- | --- | --- |
| 途中までしか取れていない | 検索件数の上限、ページ送りの打ち切り、入口に出ている種別だけを歩く | legal-square の 100 件上限（1-1）、dbsr の会議種別（1-4）、仙台市が 1991 年で止まる（第58） |
| 決め打ちが外れて 0 件 | 目次・本文・添付の場所や系統名を決めつけ、外れると静かに 0 件で終わる | d1-law の目次（第51）、決め打ち 10 件（第53） |
| 取れているのに読めていない | 日付・原典 URL・本文が保存データにあるのに、渡していない・読めていない | 開催日（第40〜45）、公布日の漢数字（第45）、d1-law の本文（第35）、文字化け（第37〜39） |
| 別の中身を正しい名前で出す | 空欄より悪い。誤った文書や日付が正しい名前で検索に出る | FINO の部分一致・同名自治体の URL（初期調査）、資料を会議録に（第31〜43）、施行日を公布日に（第46・第48） |
| 取れているのに公開していない | 取得は成功したのに、索引が落ちた・走らなかった・古いまま | 例規索引の全停止（第31）、公開 0 件の鳥栖市（第51）、保存の半分未満しか公開しない（第60） |
| 放置で治らない | 失敗や確認待ちの状態を誰も戻さない | 失敗の永久除外（初期調査）、待ち行列の試行上限（第61）、縮みの確認待ち（第70） |
| 取得元の住所が変わる・分からない | 登録 URL の失効、登録の誤り、取得元未特定 | 北海道町村会の版番号（第69）、取得元未特定の会議録 191 自治体（第71） |
| 取得元に無い | 公開していない、映像だけ、本文が欠けている | 公開なしの町村（第62・第69・第71）、YouTube だけ（第54）、例規の本文が取得元に無い 3 自治体 |

## 直したもの

型ごとに主なものを 1 行ずつ挙げる。

### 途中までしか取れていなかったもの

- legal-square の検索件数の上限（100・250・500・1000）を種別＋制定年月日の再帰分割で越える。福岡県は 1,000 → 1,221 件で補助金等交付規則が入った（1-1、3 章 A、6 章「福岡県 例規の結果」）
- legal-square の「次へ」が最終ページでも止まらない、不正な日付や差し替え待ちで古い件数を読む（1-1、3 章「済んだこと」、6 章「外部レビューで見つかった穴」）
- 単日でも上限に張り付く区間（合併の日）を件名のキーワードで割る。21 自治体、宮古市は 100 → 174 件（「飛騨市」、第69）
- dbsr の会議種別を検索フォームから全部読む。福岡県は一覧 3 → 50 ページ（1-4）
- 年度別一覧が本会議だけでそろっていても完了にしていた。検索フォームの種別と突き合わせて補い、補った分に種別を付ける。委員会が欠けていた愛知県・広島県・甲府市・西尾市で委員会が入った（1-3-4、1-3-3-1、「年ディレクトリが全角と半角に割れる」）
- 年ラベルの衝突で、同じ月日の会議が年をまたいで 1 件に潰れていた。愛知県は 1,052 → 2,993 会議（6 章「外部レビューで見つかった穴」）
- gijiroku.com 旧形式の `KGTP=1,2` 決め打ち。大田区の委員会 0 → 76（1-3-5）
- 取得元が示す会議種別を記録し、監査で「取りこぼし」と「登録先は本会議のみ」を分ける（1-3〜1-3-3、1-3-6）
- 千代田区の会議種別「トップページ」を名づけ直す。dbsr・gijiroku.com で種別から年・回次を落とす（1-3-7、3 章 D）
- dbsr のページ送り失敗と、例規の全件取得で「次へ」が止まった場合を未完了に数える（「歩き切れなかったのに complete になる経路」）
- キーワード一覧（`Phrase=`）を年度別一覧と取り違えていた（東郷町ほか 8 自治体）（「キーワード一覧を年度別一覧と取り違えていた」）
- gijiroku.com の会議リンク `ACT=100`・`ACT=200` と年リンクを辿る。富士市 14 → 1,666 件、太田市 7 → 1,038 件（第54）
- gijiroku.com の本文を `ACT=203`・`HATSUGENMODE=1` で取る（高崎市・狭山市）（第57、第58）
- 仙台市のページ送りが 0 件のページで終わっていた。「最後」の番号で続け、時間切れでも集めた行を捨てず、次回は続きから歩く（第58）
- dbsr の全文表示（`doc-all-frame`）で枠の文言を本文として保存していた（24 自治体）（第59）
- 一覧の取得がタイムアウトすると自治体まるごと失っていた（西宮市 5,067 件中 9 件）（第55）

- 取得元のリンク切れや外部保存先の拒否を取得エラーに数えていた。`source_missing`・`external_unavailable` に分ける（第71）

## 残っている課題

### 未対応

- **例規の番号を題名から拾う**（legal-square、マニフェスト 44,201 行中 217 行）。`_cell_after_title` が題名セルを除いていない。直すと保存名（`stem_for`）が変わって二重登録になるので保留している。旧 stem のファイルがあれば使い続ける案がある（1-1-2、collection-design-issues.md の型 C）
- **例規の題名が途中で切れる**（川崎市 2 件、ルビの直前）（「未対応: 例規の題名が途中で切れる」）
- **gijiroku.com の原典 URL が検索結果ページ**で、同じ検索結果から取った文書が同じ URL を持つ。取得元が検索条件を要求するので、文書 1 件の URL に絞れない（第34、第35）
- **委員会記録を別の URL で公開している自治体**を登録できない。登録簿が 1 自治体 1 URL（型 F）。米子市で確認し、小美玉市・赤磐市は未検証。「登録先は本会議のみ」の 233 自治体の別 URL 調査も未着手。第55 で本文から数えたときは実害を確認できず、優先度を下げた（1-3-6、第55）
- **委員会の取りこぼしを機械で判定できない 79 自治体**（kensakusystem 65・独自 12・static 2）。kensakusystem は会議数の多い順に手で当たる予定だった（1-3-6、3 章 C）
- **胎内市**（kaigiroku.net）は、取得元が委員会を示しているのに 1 件も収録していない（1-3-3）
- **原典が同じ URL のまま訂正されても取り直さない**。取得済みの会議録は同じ URL では取り直さない（6 章「放置では治らないもの」5）
- **原典から消えた文書を索引から取り除く経路が無い**。保存ファイル・マニフェスト・OpenSearch の三つが正本になっている構造は残っている。第55 では孤児は出なかったが、種別判定が効いているためで、構造の保証ではない（6 章「放置では治らないもの」4、第55、型 D）
- **legal-square の制定年月日の区間は、来年以降の公布日を含まない**（6 章「年ラベル修正で持ち込んだ回帰」）
- **飯綱町**の `令和元年第４回臨時会（１０月９日開会・閉会）` は開催日が空（第48）
- **日付が読めないだけで `stale` に出る会議録**（嵐山・豊前・大多喜・和水・葉山・清水・真室川）。題名に月日が無い（第62）
- **文字化けの残り 0.09%**（垂井町の議会だよりなど、標本 9,948 ファイル中 9 件）は、どの符号化で読み直しても戻らない。元の PDF を別の方法で読むしかない。落とさずに残している（第50）
- **差分ハーネスが日付しか比べない**。文書の増減・題名・本文・原典 URL の回帰は止まらない（第55 の指摘）

## 放置で治る仕組み

- 各自治体は前回の確認から 30 日で再取得の対象に戻る（`FRESHNESS_SKIP_DAYS = 30`）。失敗は 7 日後、起動直後の失敗は 1 日後に再試行する（6 章、第63）
- 取り切れない自治体は、進んでいればすぐ続け、進まなければ 24 時間待つ（第61、第71）
- 索引の失敗は待ち行列を 10 分おきに掃いて投げ直す。試行上限に達しても 3 日おきに試す（第31、第61）
- 解釈を直したら、世代が古い自治体を 1 時間ごとに再索引へ積む（第48）
- 公開 0 件の自治体は 6 時間ごと、保存の半分未満しか公開していない自治体は 1 日 1 回、再索引へ積む（第51、第60）
- 本文が空・極端に短い自治体は `--no-resume` で取り直させる（1 回 2 自治体、同じ自治体は 3 日空ける）（第58、第59）
- 版番号の変わる取得元は巡回の前に引き直し、URL が空の自治体は 6 時間ごとに探す（第69、第70）
- 同じ縮み方が日をまたいで 3 回再現したら取得元の変更として受け入れる（第70）

## 繰り返し出た失敗と教訓

- **件数減を「直った」と読まない。** 減ったのは二つある原因の片方だけ（第32）、再索引していないだけ（第37）ということがある。中身を開いて確かめる（第33）
- **空が 0 になっても中身が合っているとは限らない。** 空の原典 URL を 0 にしたら、同じ URL を複数の会議が共有していた（第34）。空欄より「もっともらしく誤る」形を探す（第48、第56）
- **「対象は N 件」と書いたら内訳を見る。** 令和だけ読んで平成 10,546 件を落とした（第41）。ゼロ埋め 2 桁だけ読んで 44,581 件を落とした（第42）
- **自分が入れた回帰が繰り返し出た。** 未定義変数で 10 時間停止（第31）、`necessityScore` の復活（第36）、`DX` の消失（第37）、`平成11年` の畳み（第40）、例規の worker で会議録を索引して 0 件（第56）、入口を直して本文を確かめない（第57）、BOM（第68）。分岐を足したらその分岐を実データで踏むテストを付け、`PARSER_GENERATION` を上げる前に `parser_diff.py` を通す（第37、第52）
- **落とす判定は本物を狙う。** 札幌市の委員会記録 963 件、地方税法第404条を引く条例 17 件、昭和22〜24年の会議録 318 件を消す手前で止めた。落とす判定を入れるたびに、実データで誤って落ちる数を測る（第31、第38、第40）
- **修正を入れたら、その場で本物を外す形を列挙して測る。** 外部レビューを待たずに同じ日のうちに穴が見つかる（第44、第45）
- **読めない日付を別の日付で埋めない。** 利用者は制定日だと思って読むので、空より悪い（第45、第46、第48）
- **決め打ちをやめて書いてあるものを読む。** 読めないときだけ推測し、推測したことを記録する（第53）
- **観測できなかったことを 0 や空にしない。** 台帳自身が計測の失敗を 0 件にしていた（第55、第56）。数えていないものは「問題が無い」ではなく「見ていない」（第55）
- **「直した」と「届いた」は別。** 再索引するまで公開は古いまま。「本日再索引済み」だけでは、どのコードで載ったかは決まらない（第33、第36）
- **「届かない」「取得元に無い」「機械的には尽きた」は、探し方を変えていないだけのことがある**（第54、「御宿町は会議録を公開していなかった」の追記、第71）
- **保存先が変わる修正は、旧成果物の掃除まで 1 組で考える。** 掃除には「減っていないこと」の確認を付ける。長い取得を流してからコードを直さない（6 章「作業のときに踏んだ罠」）
- **件数の一致を根拠と取り違えない。同名は同一ではない**（「走査記録を「消えない場所」へ移した」、「年ディレクトリが全角と半角に割れる」）
- **呼ぶ側に覚えさせると必ず漏れる。** 判定は値を集める場所で 1 回だけ行う（「キーワード一覧を年度別一覧と取り違えていた」）
- **懸念は測ってから動く。** 測れば下ろせるものがある。測らずに設計を直すと、実害のある穴を後回しにする（第55）
- **同じ問いを繰り返しても、見ていない観点の欠陥は見つからない。** 観点を変える（「別の自治体の例規が、その自治体のものとして公開されていた」、第35、第57）

## 調査の再現手順

### サーバーへコマンドを送る

`deploy/remote_exec.py` を使う。`deploy.json` の鍵設定を読んで SSH で実行する。

```sh
python deploy/remote_exec.py deploy.json -- "cd ~/services/miyabe-tools && docker compose -f docker-compose.scraping.yml ps"
python deploy/remote_exec.py --script-file probe.py --python deploy.json
```

`--script-file` と `--python` は `deploy.json` より前に置く（後ろに置くとリモートのコマンドとして渡ってしまう）。

- 共有データ: `/mnt/big/miyabe-tools`（`gijiroku` / `reiki` / `work`）
- スクレイパ: `docker compose -f docker-compose.scraping.yml exec -T scraper-gijiroku ...`
  （例規は `scraper-reiki`、索引は `scraper-gijiroku-index` / `scraper-reiki-index`）
- Git Bash から `/tmp/...` を渡すときは `MSYS_NO_PATHCONV=1` を付ける。付けないと
  Windows のパスへ変換されて失敗する。

### 例規の件数を数える

```sh
cd /mnt/big/miyabe-tools/reiki
for d in */; do n=$(find "$d/html" -type f 2>/dev/null | wc -l); echo "$n ${d%/}"; done | sort -rn
```

`reiki_system_urls.tsv` の `system_type` と突き合わせ、丸い数字（100・250・500・1000）に
固まっていないかを見る。

### 会議録の会議種別の偏りを数える

```sh
docker compose -f docker-compose.scraping.yml exec -T scraper-gijiroku python tools/gijiroku/audit_meeting_types.py --only-issues
```

系統ごとの集計は stderr に出る。`--system dbsr` で系統を絞れる。判定は次のとおり。

- **取りこぼし** — 取得元は委員会があると言っているのに 1 件も無い。直すべき対象
- **登録先は本会議のみ** — 登録した取得元にも委員会が無い。別の URL で公開していることがある（米子市）
- **本会議のみ(未確認)** — 取得元の言い分をまだ記録していない。下の probe を先に走らせる
- **種別不明 / 種別=表題** — 会議種別が使える形で残っていない

出るのは下限である。別の URL の委員会記録、本文を取れたかどうか、一部の委員会や
年度だけの欠けは見えない（1-3-6）。取得元の言い分は、全件取得をやり直さなくても次で集まる。

```sh
docker compose -f docker-compose.scraping.yml exec -T scraper-gijiroku python tools/gijiroku/probe_offered_meeting_types.py --system dbsr
```

`--system` は dbsr / kaigiroku.net / gijiroku.com。kensakusystem と独自は対象外
（前者はツリーを全部歩くので提示＝収録、後者は共通の読み取り口が無い）。

docker compose -f docker-compose.scraping.yml exec -T scraper-gijiroku-index \

### 台帳と監査の道具

- 台帳: celery が 12 時間ごとに `data/background_tasks/coverage_ledger.json` へ書く

  `python tools/reiki/audit_reiki_consistency.py --only-issues`

  `python tools/gijiroku/discover_minutes_urls.py --codes <jis_code>`

### MCP で検索して確かめる

```
POST https://tools.miya.be/mcp
Accept: application/json, text/event-stream
{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"search_minutes","arguments":{"q":"...","municipality_code":"40000"}}}
```

`municipality_code` は全国地方公共団体コード（福岡県は `40000`）。
`sort` は `date` または `relevance` のみ。`per_page` は最大 50。
既定の並びは会議録（`search_minutes`）が日付順、例規（`search_reiki`）が関連度順。
