**区分は専用欄の割合で決める。決まりどおりでは必ず探す項目は事業名の1項目だったが、1.2.0で境目の担当部署・今後の方向性をユーザーの判断で加え、必ず探す3項目・標準任意16項目・raw_fields 3項目とした。** 1.0.0の10・11・1、1.1.0の1・18・3から変更する。これは提供された見本で確認できた様式の分類であり、自治体の全公表資料を悉皆調査した結果ではない。

## 目的と方針


サイトは事業の良し悪しをAIで評価しない。自治体の原典をそろえ、構造化し、利用者が原典や自分のAIで確かめられるようにする。様式に項目があるかどうかを事実として示し、自治体の評価方法の優劣は述べない。

会議録・例規と同じく、原典URL、見つけたページ、文書ID、取得したファイルとの対応を失わない。今回決めた形式は三段である。

1. **文書**: 取得器のmanifestを維持する。原典URL、発見ページ、年度、種別、頁数、本文の状態と本文を保持する。manifestの年度を、そのまま評価年度には転用しない。
2. **事業評価の記録**: 1事業×1評価年度×1評価主体・段階。同じ年度に内部評価と外部評価、一次評価と二次評価があれば別記録にする。
3. **自治体ごとの読み替え表**: 記号・原文・意味・根拠の文書と頁を保持する。年度、様式、評価主体の範囲を付け、自治体をまたぐ共通の点数は作らない。

前例は[会議録](gijiroku.md)、[例規](reiki.md)、[検索](search-ranking.md)、取得の状況は[URL調査](hyoka-url-survey.md)と[取得器](../tools/hyoka/scrape_hyoka_docs.py)を参照。既存APIや検索コードの変更は今回の作業に含まない。

## 決まり：専用欄と自由記述を分ける

同じ欄を目的・内容・対象・実施結果・理由・課題などへ重ねて数えた1.0.0の方法を改める。欄が明示する意味と、文章から読み取れる意味は別に記録する。

| field_kind | 判定 | 割合と記録の扱い |
|---|---|---|
| dedicated | その項目の専用欄、見出し、質問、列・行がある | 専用欄の割合と「どこかに記載」の割合の両方に数える。標準の値に転記できる |
| embedded | 専用欄はなく、別の欄の文中に書かれている | 「どこかに記載」の割合だけに数える。原文の欄全体をraw_fieldsに残す |

「事業名・事業内容」のような複合見出しは、その二つの意味に限ってdedicatedにする。「課題及び今後の取組方針」は課題と方向性の専用欄であり、そこに書かれた目的・対象・実績をdedicatedにはしない。本文内でも「【目的】」「対象者：」など独立した小見出しがあれば専用の表示に含める。欄名だけの機械判定はしない。

**embeddedを標準の値に入れない理由は、文章から意味を分ける解釈を避けるためである。** サイトはAIで事業を評価せず、原典をそろえて利用者が自分のAIでも確かめられるようにする。自由記述をAIで「目的」「課題」などに分解して確定値として載せると、原典の欄とサイトの解釈の境目が消える。原文の欄名・全文・頁を残し、その解釈は利用者に委ねる。この決まりは「必ず探す項目」と「標準任意」の両方に適用する。

同じ自治体の別の見本文書に専用欄があれば、自治体の和集合ではdedicatedとする。最初に拾った例がembeddedでも、専用欄の別の例・頁を追加して根拠を残す。ただし、**自治体全体でdedicatedだからといって、個々の事業記録の別欄の文中から値を埋めてよいわけではない。** 記録ごとに欄を確認する。

| 意味の境界 | 専用欄として数える範囲・区別 |
|---|---|
| 目的・内容・対象 | 「事業概要」は内容。「目的」「対象者」等が別に明示されない限り目的・対象にはしない |
| 評価年度／対象年度 | 評価実施年度・作成日と実績の対象年度を分ける。表題等の固定表示は適用範囲を確認。費用の最新列だけから対象年度を決めない |
| 事業の期間 | 開始・終了・単年度・繰返し等の欄。上位計画の期間や施設建築年は別 |
| 財源／人員 | 財源内訳、人数・人工・時間・人件費の欄。任意の活動指標名に費用や職員数が出るだけで別の専用欄とはしない |
| 指標／実施結果 | 指標名・単位・目標等の欄と、明示された実績列。決算額だけを成果に数えない |
| 評価区分／方向性 | 「評価区分」の専用欄が方針の意味を兼ねるだけなら、方向性はembedded。方針も明示する複合見出し・選択欄なら両方dedicated |
| 理由／課題 | 所見・評価理由・評価コメントは理由。そこに課題の文章があるだけなら課題はembedded |
| 評価主体 | 評価者・一次二次・内部外部の明示。担当部署や記入者だけからは推定しない |
| 前回評価を受けた改善 | 前回の評価・指摘に対する対応欄。前年の方向と今年の成果が横並びであるだけでは専用欄にしない |

1.0.0で確認した範囲は265文書、計1,602頁。今回の専用欄の再確認では95自治体の447頁を見た。文書・頁の数は自治体内の確認箇所を合計したもの。**長い報告書の全頁を見たわけではなく、今回265文書全頁を再点検したという意味でもない。** 前版では本文・目次で様式の切替を探し、冒頭・中ほど・末尾と判断に必要な頁を画像で照合した。今回も本文は頁を探す補助とし、各「ある」の根拠頁と必要な追加頁の画像で欄を確かめた。画像確認はCodexによるもので、人による二重確認ではない。

各自治体のJSONにmanifest・SHA-256・旧判定・専用欄の判定・根拠画像と頁・理由を保存した。従来の「ある」の例・原文欄名・頁は消さず、必要ならdedicated_evidenceを加えた。「無い」は前版で見た頁範囲を維持する。欄が空なら、様式には欄があると数え、例の値が空であることを記録する。名寄せは `work/confirmed_v3/decision_rules.md` と `semantic_mapping.csv` で追える。

## 割合と95%の幅の出し方


1自治体を1単位に数える。同じ様式が数百頁ある自治体も1票。素の割合は「ある自治体数 / 95」。重み付けした割合は、層hの当初の重み `w_h = N_h / n_h` を維持し、次の式で求めた。

```
重み付き割合 = Σ（対象に含めた自治体の重み × 項目があるか0/1）
               / Σ（対象に含めた自治体の重み）
対象の重みの合計 = 333.677248677248
```

除外した5団体を0票として残さず、分子と分母から外す。除外後の人数でN/nを作り直すこともしない。これは「事業単位の評価表が確認できた範囲」に限る比率である。

素の95%幅はWilson区間（n=95）。重み付きの幅は、Kishの有効標本数 `n_eff=(Σw)^2/Σw²=83.3635559500` を使ったWilson区間。z=1.95996398454として、中心 `(p+z²/(2n))/(1+z²/n)`、半幅 `z×sqrt(p(1-p)/n+z²/(4n²))/(1+z²/n)` から求めた。有限母集団補正は使っていない。

この幅は区分の境目への近さを示す**95%参考区間**である。差し替えは無作為な再抽出ではなく、自治体内の文書・頁も無作為抽出ではないため、全国への厳密な95%信頼区間とは主張しない。同じ計算を専用欄のみ、専用欄＋文中の記載の二通りに適用した。後者は1.0.0の値と一致することを検証した。

事業名・評価年度・対象年度・評価主体の4項目は、割合とは別に記録を識別するため状態を必須にする。1.2.0では必ず探す担当部署・今後の方向性の状態も必須にしたので、Schemaの必須項目は合計6（事業名は両方に入る）。評価年度等が分からなければ取得年度で埋めず、仮の記録IDと理由を付ける。

## 記録のSchemaと値がないとき

[evaluation_record.schema.json](../tools/hyoka/schema/evaluation_record.schema.json) はJSON Schema draft 2020-12、版1.2.0。Gitの対象になる `tools/hyoka/schema/` に置く。`$id` は識別子であり、そのURLで公開済みという意味ではない。

`fields` に19の標準名を定義し、識別用4項目の状態を必須にする。対象・受益者、根拠法令、前回評価を受けた改善は専用欄があってもraw_fieldsに残す。今回の22項目にない欄も捨てない。同名の欄を上書きしないよう、配列と `section_path / occurrence / field_id` で原文の欄を区別する。

各標準項目は `field_kind / status / value / raw_label / raw_text / evidence / note` を持つ。`present` は `field_kind: dedicated`、nullでないvalue、原文の欄名・値・出典を必須にする。欄があるが空白ならfield_kindはdedicated、statusはnot_recorded。専用欄なしはabsent、確認途中の欄はunverifiedで表せる。欄の種類と値がない理由を混ぜない。

embeddedしかない場合、標準項目を記録するときは `status: represented_elsewhere`、`field_kind: embedded`、`value: null`、`raw_text: null` とし、`related_fields` でraw_fieldsのfield_idを参照する。raw_fieldsには元の欄名と**欄全体の原文**を一度だけ保存する。そこでは `canonical_field: null` とし、`interpretation` を付けられない。複数の意味へ分けた抜粋を作らない。専用の複合欄として転記する標準値と原文保存が同じ欄を参照することはある。

| status | 意味 | 扱い |
|---|---|---|
| present | 値あり | 標準の値は専用欄のみ。raw_fieldsでは元の自由記述全文も保持できる |
| unreadable | 読み取れず | OCR失敗等。記載なしとはしない |
| other_document | 別文書にある | other_document_hint必須。未取得ならそう書く |
| represented_elsewhere | 書き方が違う | related_fields必須。embeddedの意味を標準の値へ読み替えない |
| not_recorded | 記載なし | 確認した頁と範囲を付ける。欄自体がないのか、空欄なのかも残す |
| not_applicable | 該当しない | 新規事業・廃止済み等、原典で理由を確認できる場合だけ |
| unverified | 取り出し途中 | 再開用。今回の2,090判定と6例には使わない |

raw_fieldsのfield_kindも、共通の意味への対応を示す印である。専用欄ならcanonical_fieldに対応先を付けられる。自由記述の文中にある意味を保存する場合はembedded・canonical_field:nullであり、「原典にその自由記述欄自体がない」という意味ではない。

各 `evidence` は `doc_id`、`source_url`、`page_url`、SHA-256、位置、原文の抜粋、取り出し方、確からしさとその理由、確認状態を持つ。PDFの頁は1始まりの物理頁で、紙面の頁番号は別項目。Excelではシート・セル範囲に加え、固定した描画物の文書IDと頁を必須にする。Wordも段落の場所と描画物の頁を付ける。頁を持たない元ファイルからでも、利用者が同じ場所を見られるようにする。

取り出し方は `excel / pdf_text / ocr / ai_extraction / manual_transcription` の配列。AIは原典の抜き出しに使い、事業の評価を生成するためには使わない。確からしさは抽出値の一致についてであり、自治体の評価の信頼性の採点ではない。人が確認していない記録を `human_reviewed: true` にしない。

自治体のコード・名前は `identity_source` で台帳由来を明記する。原典の評価値とは分ける。記録IDや正規化コードなど生成した管理値は、作り方又は読み替え表で説明する。

### 年度・費用・指標

評価年度と対象年度を分ける。対象期間が複数年度なら `target_year.value` に年度の配列を使う。年度ごとの費用や指標の比較欄があるだけでは、全年度を評価対象にしない。評価年度や主体を特定できなければ `record_status: provisional` のまま保存できるが、他の年度・主体の記録とは統合しない。事業名・評価年度・主体がそろった場合に `identified` にできる。

金額の `amount_yen` は**円単位の十進文字列**。例として「2,976千円」は `"2976000"`。二進浮動小数による桁落ちと円未満の丸めを避ける。原額・単位・換算式・金額の年度を残し、予算（当初・補正等）／決算／見込／原典で単に実績と書かれた額を区別する。人件費込み・除外・人件費のみ・不明、現金主義・発生主義・混在・不明も保持する。原典にない条件を推定しない。

費用は複数年・複数種類の配列。財源も名称と出典付き金額の配列。人員は人数・人工・時間等の単位と年度を伴う測定値にし、人件費しかない場合は数量の欠ける理由と費用を保持する。指標は名称、活動／成果等の種別、年度、単位、予定・目標・実績等の役割を持つ。横並びの列を混ぜない。

## 方向性・評価区分の読み替え


`future_direction` は原文、観点（事業内容／予算／混在／未特定）、読み替え語、対応表の行ID、対応状態を持つ。複数の方向は `combined`、選択肢を区別できない場合は `alternatives` とする。検討・予定の語は `decision_stage` と原文に残し、実施決定と扱わない。

| 読み替え語 | code | 見本にあった原文の例 | 注意 |
|---|---|---|---|
| 拡充 | expand | 拡充、拡大、充実、重点化 | 予算拡充なら観点を予算とする |
| 継続 | continue | 現状維持、現状継続、現行水準、継続実施（変更なし） | 条件付や優先等の原文は残す |
| 改善 | improve | 見直し、方法改善、手段改善、効率化、改革 | サイトが改善の必要性を判断するものではない |
| 縮小 | reduce | 縮小、縮減、機能の縮小 | 減額だけなら予算の観点 |
| 統合 | integrate | 他事業と統合する、整理統合、施設の統合 | 統合と廃止が両方明記なら両方保持 |
| 休止 | suspend | 休止、事業凍結 | 廃止と分ける |
| 廃止 | abolish | 廃止、次年度廃止、5年以内廃止 | 廃止検討は決定と扱わない |
| 完了 | complete | 完了、事業完了、目的達成 | 予定か実施済みかを分ける |
| 終了 | end | 終了、事業終了 | 完了・廃止のどちらかを推測しない |
| 新規 | new | 新規、新規採択 | 現在の事業種別と今後の判断を区別 |
| その他 | other | 民営化、民間移管、終期設定、連携・協働実施等 | 原文を残し、別の語へ無理に寄せない |

「改善して継続」はimprove＋continue。「休止又は廃止」はsuspend／abolishの選択肢を保つ。「成果拡充・コスト縮小」のように成果と費用が混在する語を、事業の拡充又は縮小に一つにまとめない。与謝野町のE「予算拡充を伴う見直し」は、事業内容の見直しと予算拡充の二つの観点を保つ。

評価区分は `raw_term / dimension / meaning / mapping_status / mapping_entry_ids` を持つ。同じA・B・Cでも自治体・年度・段階で意味が違うため、共通の大小・偏差値・良否へ変換しない。秋田県の研究課題の中間評価ではAが9～8点、事後評価ではAが6点であり、同じ自治体でも表を分ける。凡例がなければ記号を原文で保持し、意味を推測しない。

読み替え表はSchemaの `$defs.vocabulary_table` で独立して検証できる。適用範囲は自治体、評価年度の始終、評価主体、様式名、版の説明。各行には原文の語、出典付きの意味、読み替え語、観点、関係、根拠の種類を置く。`official_legend`（公式の凡例）、`explicit_source_wording`（原文の明示語）、`proposed_interpretation`（設計上の読み替え案）を区別する。根拠が提案のままなら公式の対応とは表示しない。

1.1.0では表に `application_policy: dedicated_fields_only` を必須にする。各行には `source_field_kind: dedicated` と実際の `source_label` を付け、`application` を明示する。`proposed_interpretation` は必ず `proposal_only` とし、記録のmapped値には適用しない。専用欄に明示された語でも、読み替えに解釈が必要なら原文だけを保持できる。別の欄の文中の語をこの表で標準項目に変換することは認めない。

観察語は756件、項目と語で重複を除くと574通り。凡例の選択肢も含むため、採用された評価結果の件数ではない。1.1.0の `vocabulary_proposals.json/csv` は、方向性の候補372件、自治体固有の評価区分342件、単一語に決めない38件、embeddedのみで候補を撤回した4件を記録する。宮城県の「事業推進」「事業凍結」、八頭町の「今後も継続していく」、東みよし町の「検証の上災害時個別対応マニュアルの改定予定」の4件は標準値に変換しない。

この観察表は適用済みの読み替え表ではない。自治体内に専用欄があるという判定だけでは、その語を取った個別の欄まで専用欄とは保証できない。全行をproposal_onlyとして保存し、実際に適用するときは記録の欄・頁・選択結果と凡例を照合した行だけで読み替え表を作る。記録例に入れた5表は個別の欄を確認している。島根県の提案行は適用せず、方向性の原文をunmappedで保持した。

## 取り出しと検索の進め方


1. 文書・頁の全文検索を先に作る。文書種別と評価単位を分け、事業調書、施策評価、施設分析、集計・概要を混ぜない。原典と発見ページへたどれる状態を先に確保する。
2. Excelを持つ自治体で、セルと描画頁を対応させて構造化する。今回の提供値ではExcel/CSVを持つ自治体は16に限られるので、全国対応をExcelだけに依存させない。
3. 文字のあるPDFで、事業境界・表の列位置・評価主体を確かめながら抽出する。値のない理由と信頼度を項目ごとに保持し、自治体単位の進捗を保存する。
4. 画像だけのPDFへOCRを適用する。OCRの文字を原文そのものと見なさず、画像の頁と抽出方法を残す。

提供された2026-10-28本番集計は48,268ファイル（PDF 47,849、Excel/CSV 191、Word 29、zip 199）、画像だけのPDF 1,661本・32,666頁、全頁の約4%。本作業では本番を再集計していない。取得・抽出の優先順の根拠として用いる。

抽出では、最初に元の欄と頁を保存し、専用欄の確認後にだけ標準の値へ移す。embeddedは全文検索の対象に含められるが、標準の目的・対象・課題等の値としては検索結果に表示しない。AIによる意味の分割や評価は利用者側で行う。

## 残る運用上の決定

形式と区分は1.2.0として確定した。残るのは、改称・統合された事業の年度をまたぐID、追加見本で区分を見直す時期、読み替え表の版管理、OCR値と欄判定を人が点検する範囲。原典にない年度・意味・人件費範囲は埋めない。長い報告書で今回見ていない頁の異種様式や、抽出元349自治体以外への広がりは別途調べる必要がある。
