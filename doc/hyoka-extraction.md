# 事務事業評価の機械抽出（第1段）

取得済みの原典を自治体・様式別のプログラムで読み、[共通形式1.2.0](hyoka-common-format.md) の記録にする。
入口は `tools/hyoka/extract/run_extract.py`、様式定義は `tools/hyoka/extract/templates/<団体コード>.yaml`。
ネットワーク、生成AI、要約、原典への書込みは使わない。取得器・公開API・検索への接続はこの段階に含めない。

## 入出力と実行

取得器の保存形式と、試行用の平らな保存形式の両方を読める。

```text
work/hyoka/<slug>/manifest.json
                 source/<doc_id>.pdf   # xlsx / zip も可
                 text/<doc_id>.txt.gz

pilot/<slug>/manifest_subset.json
             <doc_id>.pdf
             <doc_id>.txt.gz
```

本文の控え `txt.gz` は位置や原典の文字との一致を保証できないため、抽出の根拠には使わない。
manifest の `source_url`、`page_url`、`doc_id`、団体名・コード・slug を引き継ぐ。
`fiscal_year` やファイル名から年度や事業名を補わない。manifest に SHA-256 がある場合は取得ファイルと照合する。

```bash
python tools/hyoka/extract/run_extract.py \
  --work-dir work/hyoka --code 01100 --out work/hyoka-extracted
python tools/hyoka/extract/run_extract.py \
  --work-dir work/hyoka --all --out work/hyoka-extracted
python tools/hyoka/extract/audit_output.py \
  --work-dir work/hyoka --out work/hyoka-extracted
python -m unittest tools.hyoka.test_extract -v
```

Windows では実行可能な Python 本体の絶対パスを指定する。入力と出力を同じ場所や包含関係に置くと停止する。
`--templates` で別の定義群、`--force` で全再抽出、`--limit-docs N` で開発用の文書数制限を指定できる。
制限付きの結果には `limited: true` を付ける。通常の実行では `--limit-docs` を付けない。

```text
<out>/<slug>/records.jsonl           # 共通形式の記録、1行1件
             extract_report.json    # 文書別結果、項目の状態別件数
             source_documents.json  # 原典と派生文書の台帳
             documents/<id>.json    # 文書単位の記録・失敗・警告・様式
             progress.json          # 直近まで完了した文書
             rendered/*.pdf         # Excel の番地付き確認用写し
             audit_report.json      # 保存結果を原典から再照合した結果
<out>/pilot_summary.json             # 今回指定した自治体の集計
      audit_summary.json
```

文書単位で一時ファイルから置換して保存する。入力のバイト列、manifest の当該項目、自治体の定義、
抽出コード、Schema が同じなら完了した文書を再利用する。途中で止めても同じコマンドで続けられる。
原典・定義・コードを変えればキャッシュを無効化する。文書の例外は成功扱いにせず報告し、次の文書へ進む。
同じ出力先への同時実行は行わない。複数プロセスで回すなら自治体と出力先を分ける。

## 原典の読み方

- PDF は `pypdfium2==4.30.0` の Unicode、文字座標、文字の基線を用いる。字形の中心で行を組むと、
  小さい仮名や句読点が別の行になるため、基線で行を組み、行内を左から読む。
- 定義の座標は左上原点の比率 `[left, top, right, bottom]`。出力の `bbox` は同じ原点の PDF ポイント。
  頁番号は1始まり。値の領域に文字の中心があるものを採る。空白・改行の配置は再構成される。
- 表の行は PDF の実際の横罫線で区切る。つながった短い線分と、Excel由来の細い塗り矩形にも対応する。
  大きなセル背景の辺は行境界にしない。入れ子の Form 内の罫線は未対応。
- 原典の文字がない、又は極端に少ない頁は `needs_ocr` として飛ばす。この段階では OCR を起動しない。
  この分類には白紙や文字の少ない表紙も含まれるため、画像PDFの確定件数とは扱わない。
- xlsx / xlsm は ZIP と XML で読む。共有文字列・直接文字列・保存済みの数式値に対応し、ふりがな `rPh` は本文から除く。
  数式の再計算、書式による日付や数値の表示変換、描画オブジェクトの文字読みは行わない。
  対象セルに数式の保存値がないときは拒否する。非表示シートも報告して飛ばす。旧 xls、doc/docx は未対応。
- ZIP はディスクへ展開せず、子文書に固有 ID・SHA-256・メンバー名・親 doc_id を付ける。
  子文書の原典 URL は取得した ZIP の URL、発見ページは元の `page_url`。
  親 ZIP も台帳に残す。パス逸脱、過大な展開サイズ、二重 ZIP は拒否する。

Excel の `rendered_doc_id` / `rendered_page` は、参照セルを番地付きで並べた確認用PDFを指す。
これは Excel の印刷設定や図形を再現した画像ではない。`reportlab` は既存の scraper requirements に含まれているものを使う。
本文の証拠はあくまで原典 XLSX のシートとセル番地である。PyMuPDF、openpyxl、新しいコンテナ依存部品は使わない。

## 様式定義

13自治体に各1ファイルを用意し、複数様式・年度を `templates` の中に分けて置く。
全ての定義は、事業名・担当部署・評価年度・対象年度・今後の方向性・評価主体の6項目を持つ。
ない項目にも明示的に `absent` の理由を書く。

以下は書き方を示す架空の断片で、実際の座標ではない。

```yaml
version: 1
municipality:
  code: '99999'
  name: 例市
templates:
  - id: example-r7
    layout: single_project_sheet
    match:
      - pattern: 事務事業評価表
      - pattern: 令和7年度
        rect: [0.1, 0.03, 0.9, 0.08]
    fields:
      project_name:
        label:
          rect: [0.1, 0.10, 0.2, 0.15]
          pattern: 事業名
        value:
          rect: [0.2, 0.10, 0.9, 0.15]
      department:
        label: {rect: [0.1, 0.15, 0.2, 0.20], pattern: 担当課}
        value: {rect: [0.2, 0.15, 0.9, 0.20]}
      evaluation_year:
        label: {rect: [0.1, 0.03, 0.9, 0.08], pattern: 評価表}
        value: {rect: [0.1, 0.03, 0.9, 0.08], pattern: '(令和[0-9]+年度)'}
      target_year:
        absent: 専用の年度欄がない。評価年度から1を引かない。
      future_direction:
        label: {rect: [0.1, 0.7, 0.9, 0.9], pattern: 今後の方向性}
        value:
          rect: [0.1, 0.7, 0.9, 0.9]
          below_heading: 今後の方向性
          columns: [0.1, 0.9]
          rule_span: [0.12, 0.88]
      evaluation_actor:
        absent: 主体を明示する欄がなく、担当課から推測しない。
```

選択肢や文章を定数で埋める仕組みは持たない。`pattern` は NFKC と空白除去後に照合し、
マッチした範囲を元の文字列に戻して転記する。第1捕捉群があれば、その原文範囲だけを採る。
括弧・丸数字など、正規化で変わる文字にも注意する。

使える主な指定は次のとおり。

| 指定 | 動作 |
|---|---|
| `match` / `exclude` | 固定見出しと必要に応じた領域で、様式を採用・除外する。複数様式に合えば拒否 |
| `pages` / `continuation_match` | 1事業分の頁数と、続きの頁に必ずある見出しを確認 |
| `next_page_pattern` / `next_page_not_pattern` | 同じ先頭頁を持つ1頁版・2頁版を次頁の見出しで分ける |
| `page` | 項目のある頁。事業の先頭を0とした相対頁 |
| `rect` / `pattern` | 領域全体、又はその領域内の明示した文字範囲を読む |
| `anchor` / `relative_rect` | 見出しの実際の位置から相対領域を読む。重複見出しは原則拒否 |
| `anchor_index` / `heading_index` | 同じ見出しを上下ブロックごとに読む場合の0始まりの順番 |
| `below_heading` / `columns` | 見出しの下の罫線から次の罫線まで読む |
| `rule_span` | 値の左右幅とは別に、横罫線が必ず連続する内側の範囲を指定 |
| `end_rule` | 下端に使う罫線の番号。最初の線を0とする |
| `bottom_from` | 同じ事業ブロックの別欄の下端を使う。隣の事業へのはみ出しを防ぐ |
| `table` | 罫線で行を作り、番号欄等の `row_test` が合う行だけ採用 |
| `row_top` / `row_bottom` | 行ごとの上下位置を `rect` に代入 |
| `instances` | 同じ事業の一次・二次評価、又は同頁の上下事業を別記録にする |
| `raw_fields` | 対応する標準項目のない欄、混合欄、原文の表などを欄全体で残す |
| `status: unreadable` | 欄はあるが、チェック印等から値を確定できない状態を残す |

香芝市の横持ちの Excel 表のみ、`xlsx_extract.py` の `project_columns` アダプタを使う。
列、事業名行、コード行、質問行、年度セルは YAML に宣言する。
他の Excel 様式や、宣言で表しにくい文書には、原典の検証と試験を備えた別アダプタを追加する。

## 標準項目と原文の境界

専用の欄名と値を両方確認したものだけ `field_kind: dedicated` にする。
文中の意味を解釈して、担当課、方向性、課題、過去の改善等に切り分けない。
「作成日」を評価年度へ変換したり、一次評価の年月日を二次評価に流用したりしない。
評価年月日も暦年と年度が異なり得るため、専用の年度欄へ読み替えず、日付全体を原文欄に保持する。

- 値がある専用欄は `present`、専用欄の空欄は `not_recorded` / `dedicated`。
- 欄がない場合は `not_recorded` / `absent`、印などを確定できない欄は `unreadable`。
- 文中記載の既知の関係を定義で指定する場合だけ `embedded_fields` を用い、標準項目は
  `represented_elsewhere`、`value: null`、原文欄への `related_fields` とする。意味の自動判定はしない。
- 方向性や評価記号は原語のまま保存し、独自の良し悪しや共通区分に置換しない。
  `vocabulary_tables` は空、方向性の `mapping_status` は `unmapped`。
- 事業名のない候補は記録にしない。年度や主体が揃わない記録は `provisional` とする。

この段階では宣言した欄だけを取り出しているため、全記録の `completeness` は `partial_example`。
原典の全欄を保存したという意味ではない。画像による抜き取り確認も人間の確認とはせず、
`human_reviewed: false` を維持し、確認履歴は試行出力の別ファイルに残す。

`record_id` / `evaluation_instance_key` は原典・物理頁・表の行・評価段階に基づく決定的なID。
`project_key` は団体、明示されたコード、事業名、担当部署の原文に基づく。
同じ表が全体版と分冊の双方にある場合、原典ごとの観測は残る。主体や対象年度が不明な記録を
同一評価と推測して統合しない。出力件数は全国の一意な事業数ではない。

## 検証と失敗の扱い

記録を保存する前に、値と欄名を原典の同じ頁・領域から再度読み出し、NFKC・空白除去後に
連続した文字列として存在するか確認する。単語の寄せ集め、曖昧一致、言い換えは認めない。
合わない候補は記録全体を拒否し、理由を文書別ファイルに保存する。
位置の指定そのものの誤りは文字一致だけでは検出できないため、様式ごとの画像確認も必要である。

保存後の `audit_output.py` は、原典を開き直して全記録の引用、値との関係、年度変換、
URL、SHA-256、頁・領域又はセルを再照合する。Excel の確認用PDFのチェックサムも確認する。
失敗があれば終了コード1を返す。抽出本体は失敗があっても他の文書を処理して集計を作るため、
終了コード0だけを全件成功の判断に使わない。

Schema検証は追加依存を避けるため、同梱の1.2.0 Schemaが使う制約だけを `validation.py` で実装した。
汎用JSON Schema検証器ではない。未対応キーワードを検出したら起動を止める。
既存の6記録例と、専用欄の制約違反を含む自動試験で互換性を確かめる。

| 理由 | 意味 |
|---|---|
| `no_template` | 未対応様式、表紙、解説、続きの頁など。非評価文書の確定判定ではない |
| `ambiguous_template` | 複数の様式に一致 |
| `candidate_rejected` | 見出し不一致、値の不一致、必須事業名の欠落、Schema不適合など |
| `page_error` | 行の罫線が不足、続きの頁がない・一致しないなど |
| `needs_ocr` | 文字なし・少量の頁。OCRは後の段階 |
| `unsupported_file_type` | 旧ExcelやWordなど、この段で読まない形式 |
| `document_error` | 原典なし、SHA不一致、壊れた原典、その他の処理例外 |

失敗数は頁や候補・行を数えたもので、失敗文書数とは異なる。未読欄は `warnings` と項目の状態に残す。
全項目の充足率は「保存できた記録」を分母とする。未対応文書を含む全事業の網羅率ではない。

## 新しい自治体を足す手順

1. 最新年度だけでなく旧年度、1頁版・複数頁版、一次・二次、空欄の例を選び、頁画像で欄名と境界を確認する。
2. 団体コードの YAML を追加し、固定見出しを複数宣言する。必ず6項目の規則を記述し、
   標準項目と混合原文欄を分ける。年度や主体の補完はしない。
3. 見出しの小さな写し又は合成PDFで、行の混入、年度・主体の混同、空欄、拒否条件を試験する。
   原典PDFや認証情報をリポジトリに入れない。
4. 限定実行の後に自治体全体を実行し、失敗の多い頁から様式を分け直す。最低3件を原典画像で照合する。
5. `audit_output.py` のエラーが0になってから取り込み候補にする。画像の一致確認は全件の正確さを保証しない。

今回の作業からの次回見積りは、既存に似た固定調書で1様式30～60分、伸縮する報告書・一覧で1～3時間、
新しい表構造やExcelアダプタで2～4時間程度。定義・試験・3件の画像確認を含む計画上の目安で、計測済みの人時ではない。
共通処理の不具合修正、複数年度の変種、OCR対応は別に見積もる。

## 試行範囲と次の段階

対象は秋田県、島根県、札幌市、横浜市、豊島区、江東区、香芝市、本宮市、鎌倉市、吹田市、辰野町、与謝野町、茅ヶ崎市。
目的設定、調書、親事業の報告書、二次評価一覧、横持ちExcel、ZIP内PDFを扱う。
秋田県の研究課題等、島根県の別紙KPI、横浜市の細事業、茅ヶ崎市のヘッダーなし継続頁などには未対応部分がある。
本宮市・辰野町の画像によるチェック印は未読として残す。

試料の豊島区16文書には、今回の一般・詳細評価表が含まれていなかった。
設計時に保存済みだった評価表2文書を別入力として定義の検証に使い、試料の件数とは分ける。
茅ヶ崎市の44 ZIPは中身がPDFであり、Excelの試行は香芝市のXLSXで行う。

本番での案は、既存scraperイメージ内で取得済み保存先を読み取り専用に渡し、別の書込み可能な出力先に
自治体単位で実行すること。まず失敗一覧と画像点検結果を確認し、監査を通す。
既存の取得や公開検索へ自動接続せず、投入方法、重複・事業同一性、未読欄の表示を次段で決める。
この実装作業ではサーバー、コンテナ配備、公開データには触れていない。
