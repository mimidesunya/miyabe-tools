# 事務事業評価の形 2.0（共通形式）

作成: 2026-11-02。**状態: 採用（2026-11-05、ユーザー「形 2.0 を正式な共通形式にしよう」）。**
[設計の見直し](hyoka-verification-review.md)をもとに、事業ごとのシート（本体）の形を定める。[共通形式 1.2.0](hyoka-common-format.md) を置き換える。
1.2.0 は機械の抽出で読んだ 37 自治体の記録の形として残っているが、その自治体も[様式ごとの読み取り](hyoka-forms.md)を書いて 2.0 に移す
（1.2.0 には金額の数字や指標の目標と実績が無いので、変換では移せない）。項目ごとの実装の状況は末尾の「実装の状況」。

## 目的

税金の無駄遣いを検証できるようにする。

- 表示: 自治体をまたいで同じ形で見られるようにする。原典の形は確かめ用に残す。
- 検索: 自治体をまたいで絞り込み、比べられるようにする。

サイトは「無駄」と判定しない。利用者が事実の条件で絞り込み、原典で確かめられるようにする。

**川崎市に合わせて欄を作らない。** 川崎市は手本の 1 つで、どの自治体にもある考え方（体系、事業の階層、金額の年度と段階、評価の軸）を
原文の呼び名のまま持つ。自治体ごとの違いは値と凡例に入れる。

## 3 つの層

| 層 | 中身 | 使い道 |
|---|---|---|
| 原本 | PDF、Excel、HTML | 証拠。書き換えない |
| 全欄の層 | シートの全部を原文のまま | 原典の確かめ、全文検索 |
| 検証の層 | 問いに答えるためにそろえた値 | 同じ形の表示、検索、比較、集計 |

検証の層の値は、必ず全欄の層の場所（番地）を根拠に持つ。根拠の無い値は持たない。
円の金額やそろえた評価のように機械で決める値は、原文と、決めた規則（単位、凡例）を一緒に持つ。

## 文書の仕分け

文書ごとに、中身を読んで種類を決める。題名や見出しの語では決めない。

| 種類 | 扱い |
|---|---|
| 事業シート | 本体 |
| 事業の一覧表 | 本体。1 行を 1 事業とする |
| 施策の中の事業の行 | その行だけ本体 |
| 施策評価、外部評価、概要、成果説明書など | 別枠。原本と全文を持つ |
| 無関係 | 入れない。入れなかった理由を残す |

全国の調べ（1,788 団体、2026-11-03）では、事業が載る様式は 1 事業 1 枚のシート 724 団体、1 事業 1 行の一覧表 501 団体、
施策の文書の中の事業の行 286 団体（数は調べの記録の様式の説明から数えた目安）。年度によって載り方を変える自治体が多い。

年度は収集時の値を信用せず、シートの中身から取る。足立区の令和 7 年度の調書が 2016 年度、流山市の平成 30 年度が 2048 年度になっていた例がある。

自治体ごとに「どの年度に、どの種類の文書を公開しているか」を記録する。公開が途切れたことも事実として残す。

全文検索は、事業の記録の頁（`pages`）で PDF を事業ごとのシートとそれ以外に分け、シートを優先して返す（[事務事業評価の検索](hyoka-search.md)）。

## 全欄の層

PDF の頁を、表の形のまま持つ。欄の意味づけはしないので、AI を使わず、費用もかからない。

| 持つもの | 中身 |
|---|---|
| 表 | 行、列、結合、列の幅、升目の文字。空の升目も残す |
| 表の外の文字 | 頁の上からの位置と文字 |
| 縦書き | 列ごとの文字 |
| 位置の表示 | 表の外の字が 3 割以上か表が無い頁は、PDF の行ごとの文字と位置も持つ |
| 頁の状態 | 文字の層が無い、文字化け、図形が多く文字のまま |

**頁の文字は、必ず表か表の外のどちらかに入る。** 実装は `tools/hyoka/ai/grid.py` の `page_layout`。

罫線を読み取れない PDF がある（足立区など）。抜き取りでは頁の約 14% で、そうした頁は文字を原典の位置に並べて表示する。文字の層が無い頁（守口市のように文字が図形で描かれた PDF）は、そのことを表示し、OCR の対象にする。

置き場は `work/hyoka-ai/<slug>/layouts/<doc_id>.json.gz`。1 行目が目次で、そのあと 1 頁 1 行にする。画面は開いた頁までしか解かないので、大きな文書でもメモリを使わない。`build_display_data.py` が `data/hyoka/sheets/` へ写し、詳細画面の「シートの全部」で 1 頁ずつ表示する。

頁の読み取りでは次を直してから構造にする。

- 頁に回転の指定があれば、見た目の向きに直す。
- 同じ字を重ね打ちした分は 1 字にする。
- 印は列の位置が意味を持つので、見出しの下の印を動かさない。

## 検証の層

**記録 1 件は「1 事業 × 1 評価年度」。** 金額、財源、人員、指標、評価の段階は、その中に年度や段階ごとの行として持つ。
事業のシートが何頁にもわたれば、頁の一覧 `pages` に全部（続きの頁を含めて）入れる。

### 事業

| 項目 | 中身 |
|---|---|
| 識別 | 事業名、予算上の事業名、事業番号、自治体、年度をまたぐ事業 ID |
| 年度 | 評価年度、対象年度 |
| 組織 | 部、課、係 |
| 予算科目 | 会計、款、項、目と、その下の事業の原文 |
| 体系の道筋 | 総合計画の上の段から順に `{level_raw, code, name}` の並び（下の「体系の道筋」） |
| 事業の階層 | その記録の段の呼び名 `level_raw` と、親の記録 `parent`（下の「事業の階層」） |
| 分け | 同じ事業を区・地区・期・内容で分けた兄弟 `{base_name, label, kind}`（任意） |
| 主な事業か | 計画で主な事業・重点事業とされているか（原文の印） |
| 区分 | 新規か継続か、事業の種類の原文 |
| 性格 | 給付、補助、委託、直営、施設、内部管理など |
| 根拠 | 根拠法令の原文、義務か任意か |
| 対象、目的 | 原文 |
| 期間 | 開始年度、終了年度 |

款は番号でなく名称でそろえる。番号は自治体によって違う。

氏名は全欄の層に残して表示するが、検索の対象にしない。

年度をまたぐ事業 ID は、事業番号が同じなら名前が変わっても同じ事業、番号が振り直されても違う年度の文書で名前が同じなら同じ事業とする
（`tools/search/hyoka_projects.py` の `link_projects`）。

#### 体系の道筋

総合計画の体系の、上の段から事業の直前の段までを並べる。段の数と呼び名は自治体ごとに違うので決め打ちしない。

| 自治体の例 | 並び |
|---|---|
| 川崎市（令和） | 基本政策 5 誰もが生きがいを持てる市民自治の地域づくり ＞ 政策 5-2 人権を尊重し共に生きる社会をつくる ＞ 施策 5-2-1 平等と多様性を尊重した人権・平和施策の推進 |
| 基本事業を挟む自治体 | 政策 ＞ 施策 ＞ 基本事業（調べの記録で少なくとも 38 団体） |

- `level_raw` は原文の段の呼び名（基本政策、政策、施策、基本目標、基本事業など）、`code` は原文の番号、`name` は原文の名前。
- 直接目標・施策の目標など、段に付く目標の文は `goal_raw` に持つ。
- シートに無く体系図の頁にだけある段（川崎市の基本政策）は、体系図の番地を根拠にする。

#### 事業の階層

施策の文書の中の事業の行、基本事業のシートの中の事業のまとまり、事業のシートの中の細事業を、同じ形で表す。

| 項目 | 中身 |
|---|---|
| level_raw | この記録の段の原文の呼び名（事務事業、細事業、基本事業、取組など） |
| parent | 親の記録の ID。親が別の文書にあれば、その記録 |
| scope_in_parent | 親の総額の内訳か（`breakdown`）、親と別の金額か（`separate`） |

金額を足すときは、親と子のどちらか一方の段だけを足す。子が親の内訳なら親だけを足すのが既定で、子だけを足す集計も選べる。
例: 横浜市の細事業、秋田県の事業内訳 4 つ、飯田市の予算科目の複数行。

分け（川崎市の地域課題対応事業（川崎区）〜（麻生区）のように、親の記録が無く、区ごとに別の事業番号・シートを持つ兄弟）は、
それぞれが自分の金額を持つ独立した事業なので、足しても二重に数えない。`base_name` でまとめた集計もできる。

### 金額

**1 行が「事業 × 年度 × 段階 × 範囲」の 1 つの額である。** シートの表をそのまま写すのではなく、行に分ける。
1 枚のシートに何年度分も載り、同じ年度が何枚ものシートに出る（川崎市は前々年度の予算・決算から当年度の予算・見込まで 4 年分）。

| 項目 | 中身 |
|---|---|
| fiscal_year | 年度（西暦）。原文の年度の書き方も残す |
| stage | 下の段階 |
| scope | 直接費（direct）、人件費（personnel）、総費用（total）、細事業費（sub_project）、内訳（breakdown） |
| label | 原文の欄名 |
| raw | 原文の金額 |
| unit | 単位 |
| unit_source | 単位をどこから読んだか |
| amount_yen | 円にそろえた値。**円の整数**（2026-11-05 ユーザー決定「内部的には円で記録し、表示の際はさきどの形式」）。原文の値と単位から機械で換算し、読み取りのプログラムには書かせない |
| status | 下の「値の状態」 |

段階（`stage`。2026-11-05 ユーザー決定）:

| stage | 中身 |
|---|---|
| initial_budget | 当初予算 |
| revised_budget | 補正後予算（予算現額、最終予算） |
| budget | 予算（見出しで当初か補正後か決められないもの） |
| settlement | 決算 |
| estimate | 決算見込 |
| plan | 計画（計画事業費など） |
| unstated | 段階が書かれていない |

決まり:

- 段階は欄の見出しから決める。当初か補正後か決められなければ `budget` にして推測しない。
  川崎市の 2019 年度の市民ミュージアムは予算 4億4,600万円に決算 6億8,748万円（154%）で、補正を区別しないと執行率を見誤る。
- 単位は金額ごとに、その表の見出しや欄から読む。文書全体で 1 つに決めない。
- 「事業費」の語を信用しない。人件費が入るかは、シートの式と欄の組み合わせから決める。
- 人件費の数え方を残す（平均給与 × 人数、人工 × 単価、算入なし）。
- 単位が読めない値は表示だけにして、`amount_yen` を持たない。
- 「▲」「△」は負の数とする。
- 評価した年度より後の年度の決算・見込の欄は様式の空欄として持たない（川崎市は 0 と刷る）。
- 同じ事業・年度・範囲の額が何枚ものシートにあるときの採り方（集計に使う値）: 事業ごとのシートの値を先に、次に
  決算 → 見込 → 補正後予算 → 予算 → 当初予算 → 計画、同じ段階なら新しい文書（[事業ごとの索引](hyoka-projects.md)）。
- 表示は円にそろえた値を「10億7,865万円」の形にする（万円未満は四捨五入、1 万円未満は円のまま、負は「−」。
  `lib/hyoka_display.php` の `miyabe_hyoka_display_yen`、MCP の `formatYen`）。原典の値と単位は確かめ用に添える
  （画面は升目の title、MCP は「原典 1,008,569千円」）。円にできない値（「－」、空欄、単位不明）は原文のまま出す。
- 年度ごとの表示は「当初予算／補正後予算／決算（見込）／決算 ÷ 予算」の列にする。その自治体の様式に無い段階の列は空にする。
- 控え（`data/hyoka/records`）の金額と財源の表は、行ごとに `values`（原文）と同じ並びの `yen`（円の整数か null）を持つ。

### 財源

金額と同じ形で、`source` を持つ。国、県、地方債、基金、受益者負担、その他の特定財源、一般財源。

### 人員

年度、職員の種類、人数または人工、1 人あたりの額。

### 単位当たりの費用

シートに書かれたものは原文で持つ（久山町の町民一人当たり負担額、相模原市の 1 チームあたり経費）。サイトが計算した値は、計算した値と分かるように分ける
（事業ごとの索引の `indicators[].cost_per_unit_yen`。費用 ÷ 実績。割合・点数の指標には出さない）。

### 指標

| 項目 | 中身 |
|---|---|
| name | 指標の名称 |
| kind_raw | 原典の種類の書き方 |
| kind | 対象、活動、成果、不明 |
| unit | 単位 |
| direction | 増やす、減らす、不明 |
| formula | 算式、定義 |
| target_basis | 目標の決め方の原文 |
| baseline | 基準年と基準値 |
| final_target | 最終の目標 |
| values | 年度ごとの目標、実績、原典の達成率 |

- 原典が成果と書いていても、中身が活動量のことがある。原典の書き方は変えない。サイトの判定は別に持つ。
- 原典の達成率は書き写す。実績 ÷ 目標は別に計算して突き合わせる。`direction` が減らすなら、比が 1 未満を達成とする。
- 指標が無いときは「様式に欄が無い」「欄はあるが空」を分ける。

### 評価

**1 行が「事業 × 年度 × 段階」の 1 つの評価である。** 最終の段階だけにしない。

| 項目 | 中身 |
|---|---|
| stage_raw | 原文の段階の名前 |
| actor | 担当、課長、部長、行革担当、首長、外部、市民、議会など |
| status | 実施、未記入、様式に無い |
| rating_raw | 総合の評価の原文 |
| rating_scale | 凡例の段の並び（原文）と、rating_raw がその何番目か（例: 5 段階の 4 番目） |
| achievement | 目標の達成のそろえた段階（上回る、ほぼ目標どおり、下回る、判定なし） |
| overall | 総合の評価のそろえた段階（高い、中くらい、低い、判定なし） |
| aspects | 観点ごとの評価。観点の原文、そろえた観点、結果の原文、そろえた結果（高い、中くらい、低い） |
| direction_raw | 方向性の原文 |
| direction | 拡充、継続、現状維持、改善、縮小、統合、休止、廃止、完了、その他 |
| direction_axes | 事業、予算、成果、コストなど軸が分かれるときの内訳 |
| reason | 理由の全文（下の「文章の項目」と同じ形） |

**評価のそろえ方（2026-11-05 ユーザー決定「大雑把に正規化」）**:

- 自治体・様式・年度ごとの凡例を読んで、意味の軸ごとに数段階にそろえる。凡例に書かれていない意味は推測しない。原文と凡例は必ず持つ。
- 区分が目標の達成を表すなら `achievement`、事業の良し悪しの総合評価なら `overall`、「A: 拡充、B: 現状維持」のように方向性を表すなら `direction` に入れる。
- 段の数が違う尺度は、凡例の並びの上・中・下に寄せる（4 段階なら上 1・中 2・下 1 など）。寄せ方も凡例と一緒に残す。
- 観点の名前は、必要性、妥当性、有効性、効率性、公平性、優先性などにそろえる。
- 川崎市の例: 達成度 1・2 → 上回る、3 → ほぼ目標どおり、4・5 → 下回る。施策への貢献度 A/B/C → 高い/中くらい/低い。成果 b（徐々に上がっている）→ 有効性: 中くらい。方向性 Ⅱ（改善しながら継続）→ 改善。
- **1 つの点数にはしない。** 共通形式 1.2.0 では「自治体をまたぐ共通の点数は作らない」としていた。2.0 も点数は作らず、数段階の区分だけを作る。
  自己評価の甘さは自治体ごとに違う（ほぼ全部を「B」にする自治体がある）ので、そろえた評価で自治体の順位を付けない。
  自治体どうしの比べには、方向性、指標の実績 ÷ 目標、費用の増え方のような客観的な値を使い、そろえた評価は絞り込みに使う。

全国の調べでは、事業の様式 3,657 件のうち方向性は 3,292（90%）、評価区分は 3,231（88%）にある。

### 反映

評価の結果が予算や事業をどう変えたか。

| 項目 | 中身 |
|---|---|
| fiscal_year | 反映先の年度 |
| kind | 増額、減額、新規、反映なし、不明 |
| amount | 金額の形 |
| change_raw | 原文 |
| previous_result | 前回の評価の結果 |

文中にしかなくても取る。意味の解釈ではなく、書かれた数字と語の抜き出しとして扱う。

### 文章の項目

事業の説明と評価の文は、全文を持ち、全文検索と同じ形の表示の対象にする。1 項目は `{key, label_raw, text, refs}`。

| key | 中身 |
|---|---|
| description | 事業の内容・手段（どういった業務を、どのような手段で） |
| plan | その年度の計画・取組内容 |
| performance_result | 実施結果・取組の実績・成果の振り返り |
| evaluation_reason | 評価の理由（評価の段階ごと。`evaluations[].reason`） |
| issues | 課題 |
| improvement | 改善案・見直しの内容 |
| previous_issue_response | 前年度の課題への対応 |
| environment | 事業を取り巻く社会環境の変化 |
| revision_history | 過去の見直しの履歴 |
| next_plan | 次年度の取組内容・変更点 |

- **読み取りのプログラムは欄の番地 `refs` だけを書く。** 文 `text` は升目から機械で引く（升目の折り返しを詰め、原文は変えない）。
  エージェントの手間を増やさず、書き写しの誤りも入らない。
- 欄名は自治体ごとに違うので、`key` は意味で決め、原文の欄名を `label_raw` に残す。どの `key` にも当たらない文の欄は、欄名のまま持つ。

### そのほかの欄（名前と値の組）

標準の項目に入れなかった欄を、欄名と値の組で全部持つ（2026-11-05 ユーザー「共通形式にない雑多なデータは名前と値のペアのような形式で入れるもの」）。
1.2.0 の `raw_fields` にあたる。1 項目は `{label_raw, section_raw, value_raw, refs}`。

| 項目 | 中身 |
|---|---|
| label_raw | 原文の欄名 |
| section_raw | その欄が属する見出しの原文（「事業の概要」「計画（Plan）」など）。同じ欄名が別の見出しの下にあっても区別する |
| value_raw | 原文の値。選択肢なら印の付いたもの（例「☑一部委託」）。読み取りは番地を書き、文字は升目から機械で引く |
| refs | 欄名と値の番地 |

- 漏れなく持つ。シートの欄名の付いた升目は、標準の項目かこの組のどちらかに必ず入れる。読み取りの確かめ（`check.py`）で、どちらにも入らない欄名の升目を数える。
- 欄名と値の両方で検索・絞り込みができるようにする（例: 欄名「実施形態」で値「全部委託」）。画面は同じ形の項目の下に「そのほかの欄」として出す。
- 自治体をまたいで同じ意味の欄名が多く出てきたら（実施形態、SDGs、行財政改革の課題など）、欄名の読み替えの表を作って標準の項目に上げる。上げても元の組は残す。
- 川崎市の例（市民ミュージアム 令和7年度）: 実施形態 ☑一部委託、事務・サービス等の分類（分類1）施設の管理・運営、SDGsのゴール・ターゲット SDGs11 11.7、
  行財政改革第３期プログラムに関連する課題名、政策体系別計画の記載 有、組織コード 258400。

## 値の状態

0 と未記入を区別するため、すべての値に状態を持つ。

| 状態 | 意味 | 例 |
|---|---|---|
| value | 値がある | 54,020 |
| zero | 0 と書かれ、0 と読める | 那珂市の国庫支出金 0 |
| dash | 「－」「―」と書かれている | 守口市の決算「－」、川崎市の決算の財源の欄 |
| blank | 欄はあるが空 | 中井町の人件費 |
| hatched | 斜線、網掛け | 足立区の R7 の総事業費 |
| placeholder | 0 に見えるが未記入の埋め草 | 那珂市の空行の「0.」、八頭町の網掛けの 0、川崎市の翌年度の決算の 0 |
| not_on_form | 様式に欄が無い | 宍粟市の金額 |
| unreadable | 読めない | 文字化け |

検索では value と zero だけを数値として扱う。

## 検算

シートの中の関係で値を確かめる。

| 種類 | 例 |
|---|---|
| 合計 | 総事業費 = 事業費 + 人件費、事業費 = 財源の合計 |
| 積 | 人件費 = 人数 × 平均給与 |
| 差 | 差引 = 今年度 − 前年度 |
| 率 | 達成率 = 実績 ÷ 目標 |

- 検算が通らない値は、検索の値に入れず、表示だけにする。
- 通らない理由が原典にあるとき（四捨五入、親に別の内訳があるなど）は、理由を残す。
- 横浜市の収納データ作成経費は 5 年度の親が 163,339、細事業の合計が 124,839 で合わない。細事業が年度で変わるなどの事情があるので、検算の不一致は「誤り」と決めつけず、「未確認」として残す。

## 正解

`tools/hyoka/format2/truth/` に、人の目で読んだ正解を置く。`python -m unittest tools/hyoka/test_format2_truth.py` で、正解の中の検算と単位の換算を確かめる。

抽出の合否はこの正解との突き合わせで決める。

## AI の試し（2026-11-02）

AI には番地付きの一覧を渡し、値ごとに番地と原文を返させた。`tools/hyoka/format2/extract.py` が番地を確かめ、`score.py` が正解と突き合わせる。試し方は `tools/hyoka/format2/trial.py`。

正解のある 9 シート（守口市は文字の層が無いので除く）を gpt-6-luna、指示文 `format2-v3`、effort medium で読んだ結果:

| 項目 | 結果 |
|---|---|
| 金額（値） | 99 個すべて取れた。単位の誤りは 0 |
| 金額の年度 | 6 個が誤り。秋田県の「最終年度決算（見込）額」の 1 列 |
| 財源 | 49/50（上と同じ列の年度の誤り） |
| 指標の目標と実績 | 116/116 |
| 評価の段階と方向性 | 18/18 |
| 事業名と部署 | 16/18 |
| 番地の不整合 | 3 件。機械の確かめで落とした |

指示文を同じシートで直しながら測った数字なので、未知の様式の出来はこれより下がる。

試しで見つかった升目の不具合も直した。右にそろえた数字の行がつながる（那珂市の「48.92.0.0.」）、近い 2 行の字が混ざる（久山町の「実事施業方の法効の率工化夫」）。印が見えない選択肢の並びから先頭を選ぶ誤り（久山町の「A重点化」）は、指示文で防いだ。

費用: 9 シートで $0.024。1 事業の出力は約 4,000 トークンで、55 万事業なら一括処理で約 $630。effort low なら約 $400 だが、列の取り違えが増えた。値を 1 個ずつ返させる形は出力が多いので、表の行と列の意味だけを返させ、値はプログラムが升目から読む形を次に試した。その結果が[様式ごとの読み取り](hyoka-forms.md)（Codex が様式ごとの読み取りプログラムを書き、AI なしで全文書を読む）で、今の実装はこちら。

## 共通形式 1.2.0 からの主な変更

| 1.2.0 | 2.0 |
|---|---|
| 様式に載っている割合で欄を区分 | 問いと頻出項目から決める |
| 1 記録 = 1 事業 × 1 年度 × 1 段階 | 1 記録 = 1 事業 × 1 評価年度。金額、指標、評価の段階は中に行で持つ |
| 専用の欄にない値は標準の値に入れない | 意味の解釈はしないが、文中の数字と語は根拠付きで抜き出す |
| 金額は原文の文字 | 年度 × 段階 × 範囲の行に分け、円の整数を持つ |
| 評価は原文だけ。共通の点数は作らない | 原文と凡例に加え、意味の軸ごとの数段階のそろえた値を持つ（点数は作らない） |
| 予算科目、評価の観点、改善案が標準に無い | 標準に入れる |
| 対象、根拠法令は `raw_fields` | 標準に入れる |
| 体系・親子は扱わない | 体系の道筋と事業の階層を持つ |
| 値が無い理由は不明確 | 状態を分ける |
