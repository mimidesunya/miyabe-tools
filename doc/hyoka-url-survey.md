# 事務事業評価URL調査

自治体が公開する**事務事業評価**の入口 URL を全国で調べる手順です。
事務事業評価は、個々の事業について目的・成果・費用・今後の方向を書いた
評価表で、多くの自治体が PDF や Excel で公開しています。

## 会議録・例規集との違い

会議録と例規集には共通のベンダ系システムがあり、URL の形から系統を判別
できました。**事務事業評価にはそれがありません。** 各自治体が自前のページに
置くので、URL からは何も分かりません。ページの言葉で見分けるしかありません。

呼び方も揃っていません。下見で確かめた範囲では次のとおりです。

| 呼び方 | 例 |
| --- | --- |
| 事務事業評価 | 静岡市、京都市、川越市 |
| 事業評価 | 横浜市（行政運営・監査の下） |
| 行政評価 | 札幌市（下位に「評価結果」） |
| 事務事業総点検 / 事業点検 | 自治体により |

公開の形はおおむね次の階層です。

    ホームページ → 市政/行政情報 → 行政評価 → 事務事業評価 → 評価表(PDF/Excel)

## 紛らわしいもの

同じ「評価」でも、事務事業評価ではないものが多くあります。**これらを
公開ありと数えないこと。**

- **公共事業評価**: 建設事業の再評価・事後評価。国の補助事業の枠組み
- **総合評価落札方式**: 入札の方式
- **人事評価・勤務評定**: 職員の評価
- **環境影響評価**: アセスメント
- **固定資産評価**: 税
- **学校評価・第三者評価**: 施設や事業所の評価
- **行政改革**: 改革大綱の話であって、事業ごとの評価ではない

那覇市は「行政改革」のページはありますが、事務事業評価は見つかりません
でした。**行政改革だけを根拠に公開ありとしない**のは、この形があるためです。

## 探索

```powershell
python tools/hyoka/discover_hyoka_urls.py --workers 6 --save-out work/hyoka/national_survey.csv
python tools/hyoka/discover_hyoka_urls.py --codes 22100 26100 --verbose
```

公式ホームページから幅優先で辿ります。評価の語を持つリンクを優先し、
市政ハブは 2 段目までに絞ります。1 自治体あたりのページ数と間隔で相手の
負担を抑えます（既定 32 ページ・0.6 秒間隔）。自治体ごとにホストが違うので、
並列は自治体をまたいでのみ行います。

## 2026-09-17 の判定見直し

登録簿の `review_required` 509 件を実際に開いて確かめたところ、**事務事業評価
ではないものが多く混じっていました。** 拾っていた誤検出は次の形です。

| 形 | 例 |
| --- | --- |
| ウェブアクセシビリティの取組評価 | 白糠町・釧路市 |
| 電源立地地域対策交付金の事業評価報告書 | 木古内町・奥尻町・泊村ほか多数 |
| 個別施策の事業評価 | 余市町（アイヌ施策推進事業） |
| 計画案のパブリックコメント | 糸満市 |
| 総合戦略・総合計画の外部評価 | 普代村・二宮町 |
| 指定管理施設の経営状況評価 | いわき市 |
| 計画の進行管理・評価シート | 国見町（歴史的風致維持向上計画） |

そこで判定を次のように変えました。

- 題名・リンク文字が上の形を名乗るページは、本文に「事務事業評価」があっても採らない
- 強い語は前後 24 文字を見て、別制度に付いていないことを確かめる
  （「総合戦略事業評価シート」は採らない）
- 置いてある評価文書が**全部**別制度のものなら採らない。1 件混じるだけなら採る
  （岩倉市は 10 件中 1 件が総合戦略だが、残りは行政評価結果報告書）
- 「事後評価」「再評価」は行政評価でも普通に使うので、公共事業・建設事業・
  補助事業と一緒のときだけ落とす（三条市・大月市・由布市の事後評価シートは本物）
- **年度ごとの評価文書が 2 件以上並び、かつ題名が評価の入口を名乗る**なら確実とする
  （三島市「行政評価」・南知多町「事業評価」。国見町のような計画の進行管理は除く）
- 入口選択だけのホームページでは、住民向けの入口を辿る（高岡市。観光・移住は辿らない）

`recheck_hyoka_urls.py` は、登録簿に URL がある自治体を**その 1 ページだけ開いて**
判定し直します。ホームページから歩き直す `discover_hyoka_urls.py` は 1 自治体に
数十秒かかりますが、こちらは 509 件を数分で回せます。

```powershell
python tools/hyoka/recheck_hyoka_urls.py --status review_required --save-out work/hyoka/recheck.csv
```

### 子ページへ 1 階層降りる（`--descend`）

入口ページには「事務事業評価」の説明しか無く、評価表は年度ごとの子ページに
ある自治体が多くあります（小牧市「令和7年度事務事業評価」、座間市「施策評価書」）。
`--descend` を付けると、入口で決まらなかった自治体について、評価の文書らしい
同じサイトのリンク（年度つき・事務事業評価の語つきを優先）を **最大 4 本、
1.2 秒間隔で** 開き、その先に評価表（PDF・Excel、または事業名・事業費・評価の
列を持つ HTML の表）が並ぶかを見ます。

- 除外は子ページ側でも効きます。リンク文字が別制度（電源立地・総合戦略・
  指定管理・教育委員会など）のものは開かず、開いた先の題名が計画の進行管理
  （国見町の歴史的風致維持向上計画など）なら採りません
- 公社・出資法人の経営評価（青森県）も除外します
- 登録簿の URL は**入口ページのまま**にします。子ページは年度ごとに変わるので、
  確かめた子ページは `exclusion_detail` に根拠として残します

```powershell
python tools/hyoka/recheck_hyoka_urls.py --status review_required --reason needs_confirmation --descend
```

2026-09-17 に適用した結果、「有力だが添付なし」46 件のうち 14 件、「弱い」165 件の
うち 7 件を取得対象にしました。

### 会議録・例規の兆候から追いかける（2026-09-17）

本番の索引で、会議録（2021 年以降）に「事務事業評価」が出てくる自治体、
例規の題名に「行政評価」「事務事業評価」がある自治体のうち、登録簿で
`unresolved` の 401 件を追いかけました。両方に兆候がある 53 件は巡回と
検索（自治体の公式ドメインに限定）の両方、例規だけの 88 件は巡回と市区の
検索、会議録だけの 260 件は巡回だけです。

- 議会で話題になっていても、評価表を公開していない自治体は多くあります。
  見つかるのは教育委員会の点検・評価、指定管理者の評価、交付金事業の評価、
  予算資料の中の一章だけ、という形がほとんどでした
- 検索で見つかった URL が、サイト改修で 404 になっていることがよくあります
  （練馬区・石狩市・ふじみ野市）
- 登録簿の `exclusion_detail` に、調べた範囲と見つかったものを残しています。
  「公開していない」と言い切れる根拠は無いので、`excluded` にはしていません

検索で見つかったのに探索が拾えなかった形は、次のように直しました。

| 形 | 例 | 直し |
| --- | --- | --- |
| 年と度の間に括弧 | 江戸川区「2025年(令和7年)度江戸川区行政評価」 | 年度の判定を広げた |
| 文書名が制度名だけ | 那珂川市「令和6年度行政評価」、江戸川区「行政評価実施報告書」 | 評価文書の名前の判定を広げた |
| 評価の入口に評価文書が 1 本 | 那珂川市 | 入口の頁に評価文書があれば有力とする |
| 訓令式のローマ字 URL | 泉大津市・光市の `zimuzigyou` | 優先して辿る |
| 総合計画の頁に PDF が並ぶ | まんのう町（実施計画の PDF） | 有力の判定は評価文書の数で数える |

広げた分、地域再生計画・鳥獣被害防止・防衛施設周辺・過疎計画の事業評価は
除外語に足しています。

`recheck_hyoka_urls.py --from-csv` で、登録簿にまだ無い候補（`jis_code,url`）を
登録前に判定できます。

## 確信度

| 値 | 意味 | 次にすること |
| --- | --- | --- |
| `high` | リンク文字か題名に「事務事業評価」がある | そのまま取得対象にしてよい |
| `medium` | 評価の入口で、本文に「事務事業評価」か評価表を指す語がある | 中身を 1 件確認する |
| `low` | 評価らしいページはあるが、事務事業評価とは言い切れない | 人が見て振り分ける |
| `none` | 見つからなかった | 公開していないとは限らない |

**`none` は「この手順で見つけられなかった」という意味です。** Web 上での
不存在を断定するものではありません。会議録 URL 調査と同じ扱いです。

## 列

- `jis_code` / `pref_name` / `name`: 自治体
- `confidence`: 上の 4 値
- `url`: 見つけた入口
- `title`: そのページの題名
- `attachments`: そのページから直接張られている PDF・Excel の数。
  実際に評価表を置いているかの手掛かり
- `evidence`: そう判定した根拠
- `pages_fetched`: その自治体で開いたページ数
- `note`: 取得できなかった理由

## 2026-09-07 の全国調査

全 1,794 自治体を 1 巡した結果です。

| 確信度 | 件数 | 割合 |
| --- | ---: | ---: |
| 確実 (high) | 167 | 9.3% |
| 有力 (medium) | 270 | 15.1% |
| 弱い (low) | 232 | 12.9% |
| 見つからず (none) | 1,125 | 62.7% |

**公開ありと言えるのは 437 自治体（24.4%）**。うち 422 自治体は入口ページに
PDF や Excel が直接張られており（合計 8,230 本）、評価表そのものを置いて
いることが確かめられます。

種別で差があります。特別区 52.2%、都道府県 34.0%、市町村 23.7%。
都道府県別では神奈川 55.9%・東京 46.0% が高く、群馬 8.3%・石川 0.0% が低い。

### この数字の限界

**石川県の 0% は、公開が無いのではなく探索が届いていないためです。** 金沢市は
`soshikikarasagasu/digitalgyoseisenryakuka/gyomuannai/4/7059.html` に行政評価を
置いていますが、部署ページを何段も辿る形なので拾えていません。同じ理由で
`none` の中には取りこぼしが含まれます。

見つからなかった 1,357 自治体に対し、ページ数と深さを増やして追いかけ直した
ところ、246 件中 11 件（4.5%）しか増えませんでした。**巡回だけで再現率を
上げるのは割に合いません。** 再現率を上げたいなら、自治体サイト内の検索や
検索エンジンの `site:` 指定を使うのが筋です。

### 数えていないもの

- **決算の主要施策成果説明書**: 地方自治法 233 条 5 項で作成が義務づけられた
  書類で、事務事業ごとの成果を書きます（紫波町の「主要事務事業の成果に関する
  調書」など）。事務事業評価とは制度が違うので、この調査では数えていません。
  **含めるかどうかは方針の決めどころです。**
- **教育委員会の点検・評価**: 地方教育行政法 26 条による別制度。13 件が
  引っかかっており、登録簿では `education_board` の印を付けてあります。

## 評価表の取得（`scrape_hyoka_docs.py`）

2026-10-27 の方針で、サイトでは例規・事務事業の AI 評価をしないことになりました。
事務事業評価は**原典を集めて構造化し、利用者が自分の AI で確かめられるようにする**。
その第一段として、台帳の入口から評価表を取り、原典のまま保存します（構造化・
索引は後の段）。包括外部監査の報告書の取得（`tools/kansa/scrape_kansa_reports.py`）
と同じ形で、取得・保存の部品は `tools/document_crawl.py` を共有しています。

```bash
python tools/hyoka/scrape_hyoka_docs.py --code 01100 --dry-run            # 候補を見るだけ（何も保存しない）
python tools/hyoka/scrape_hyoka_docs.py --code 01100 --dry-run --verbose  # 除外の例・辿ったページも出す
python tools/hyoka/scrape_hyoka_docs.py --all --workers 8                 # 台帳の enabled をすべて
python tools/hyoka/scrape_hyoka_docs.py --all --include-review --out-dir /tmp/hyoka --summary-json /tmp/hyoka.json
```

対象は台帳の `enabled`。`review_required` は `--include-review` を付けたときだけ
（`--code` / `--slug` で名指ししたときは含めます）。

### 置き場所と manifest

    work/hyoka/<slug>/
        manifest.json               文書ごとの原典 URL・見つけたページ・年度・種別・SHA・取得日時
        source/<doc_id>.<拡張子>    取得したファイルそのもの（pdf・xlsx・docx・zip など）
        text/<doc_id>.txt.gz        抜き出した本文（頭に題名・年度・種別・出典・掲載ページの行）

文書ごとに `source_url`（原典）、`page_url`（そのリンクがあったページ）、`link_text`、
`heading`（リンクの直前の見出し）、`title`、`fiscal_year`・`year_label`・`year_source`
（年度と、それをどこから読んだか）、`kind`、`file_type`、`content_type`、`bytes`、
`sha256`、`fetched_at`、`etag`・`last_modified`、`status`（`ok` / `pending` / `error` /
`gone`）と `status_reason` を残します。自治体ごとの `last_run` には、開いたページ数、
候補数、種別ごとの数、**取らなかったリンクの理由ごとの数**、エラーを残し、
`excluded_examples` に理由ごとの例を 5 件まで残します（取り違えの点検用）。

年度は書かれたとおりに読みます（リンク文字 → 見出し → ページの題名 → ファイル名 →
URL のローマ字 `jimujigyo_r6/` → そのページへ来たリンクの年度）。「令和6年度事務事業
評価（令和5年度実施事業）」なら評価した年度の 2024 になります。対象事業の年度との
読み分けは構造化の段で行います。

### 辿り方

入口から、評価の手掛かりのあるリンクだけを辿ります。評価表・調書の語 → 評価結果 →
年度つきの評価 → 評価の入口の順に先に開き、委員会の開催ページは後回しにします。
評価のページの上では、見出しの下の年度リンクと、調書一覧の部局リンク（札幌市の
「危機管理局」など）も辿ります。同じ優先度なら新しい年度から開きます。

- 既定は 1 自治体 200 ページ・4 階層まで。札幌市は 入口 → 評価結果 → 年度 → 調書
  一覧 → 局ごとのページ と 4 段あり、15 年度分で 400 頁近くあります。辿る順は毎回
  同じなので、上限で切った先は次の回にも見えません。札幌市は 200 頁で止まるので、
  全年度を見るなら `--max-pages 500` 程度にします
- 同じ組織のホストだけを辿ります。ファイルだけは、外部の保管庫（大町市の
  `*.sakurastorage.jp`、S3 など）に置かれたものも、自治体のページに張られていれば取ります
- ファイルは 1 回に 1 自治体 `--max-docs` 本（既定 400）まで、新しい年度から取ります。
  残りは manifest に `pending` で残り、次の回に取ります。事業ごとに 1 ファイルを
  置く自治体は 1 年で数百本になります（札幌市 600、堺市 500 前後）

### 種別（`kind`）

| 値 | 中身 |
| --- | --- |
| `project_evaluation` | 事務事業評価の評価表・調書・結果報告（本体） |
| `policy_evaluation` | 施策評価・政策評価 |
| `external_review` | 外部評価・行政評価委員会などの意見・答申・具申・会議録 |
| `overview` | 評価の概要・一覧表 |

リンク文字で決め、手掛かりが無ければ見出し、ページの題名の順に見ます。概要・一覧は
リンク文字だけで決めます（北区は「…事務事業評価の概要」の頁に本体を置いています）。

### 取らないもの

**事業の名前は分野の言葉を含みます**（札幌市の「広報誌等発行費」「橋りょう長寿命化
修繕費」「（公社）シルバー人材センター運営補助金」「鳥獣被害防止対策推進費」）。
分野の言葉で落とすとこれを取りこぼすので、規則を 2 段に分けています。

- 別の制度・別の書類の名前そのものは落とす: 教育委員会の点検・評価（地教行法 26 条）、
  人事評価・給与定員管理、環境影響評価、総合評価落札などの入札、公共事業の再評価・
  事前評価・新規事業評価・大規模施設建設事業評価、交付金事業の評価、研究開発の評価、
  公社等経営評価、公営企業の局の事業評価、学校評価・第三者評価、固定資産評価、
  パブリックコメント、個別計画の点検・進行管理、主要施策の成果説明書、様式・記入例・
  意見用紙、要綱・要領・手引、市民アンケート、組織図、委員名簿・会議次第、計画書・予算書そのもの
- 別の制度の対象を指す言葉（指定管理・公社・総合戦略・地方創生・長寿命化・電源立地・
  決算など）は、**直後に評価・検証・報告などが続くときだけ**落とす。間に課・室・局・係が
  挟まるときは部署の名前なので落としません（岐阜市「監査委員事務局事業評価シート」）
- 「事務事業」と書いてあれば、総合戦略・地方創生・教育委員会・指定管理・決算の言葉が
  混じっても取ります（地方創生交付金の効果検証は、事務事業評価と名乗る場合だけ取る）
- 見出し・ページの題名が別制度を名乗るときは、その下のファイルも取りません
  （板橋区の指定管理の頁の「サービス水準評価結果」）。入口の題名が別制度を名乗る
  自治体は、実行の終わりに「台帳の確認が要る」として並べます

### ファイルの形式と本文

PDF は包括外部監査と同じく pypdf で本文を抜き、文字の無いものは `needs_ocr` にします。
xlsx・xlsm・docx は標準ライブラリ（zipfile と XML）だけで本文を抜きます。取得イメージ
（`docker/scraper/requirements.txt`）に openpyxl・python-docx・xlrd は入っていないので、
**xls・doc（古い形式）、pptx・ods・odt は保存だけで本文は抜きません**（`unsupported`）。
ZIP は展開せずそのまま保存し、中のファイル名を manifest に残します。CSV は文字コードを
当てて読みます。

評価表をファイルにせず HTML の表だけで載せている自治体は、実行の終わりに
「HTML の表だけ」として並べます。表の読み取りは後の段です。

### 取得元への配慮

1 件ごとに 1.5 秒空けます（`--delay`、1 秒未満にはしない）。`--workers` で並べるのは
入口のホストが違う自治体どうしだけで、同じホストは 1 本の流れで順に取ります。一度
取ったものは 30 日問い合わせ直さず、問い合わせるときも ETag / Last-Modified の
条件付きにします。同じホストで接続を続けて切られたら、そのホストを 6 時間休みます
（記録 `host_blocks.json` は自治体をまたいで共有）。取得元から消えた文書は `gone` と
記録し、保存物は消しません。入口が開けなかった回は判断しません。

### 2026-10-27 の試行

`--dry-run` で 64 自治体（都道府県・政令市・特別区・中核市・一般市・町村）を見て、
規則を直しました。無作為に選んだ `enabled` 30 自治体では、1 自治体の候補は中央値 15 本・
平均 95 本で、裾が長くなっています（芽室町 848・池田市 470・小牧市 290）。開いたページは
平均 7 頁。リンク文字の大きさの注記から見ると 1 本 0.6〜0.9 MB です。小さな 3 自治体
（阿見町・南箕輪村・座間市）で実際に取ったところ 30 本・179 MB で、全部本文を抜けました。

全件（`enabled` 436）の見積もりは 4.5〜5 万本・30〜40 GB（標本が 30 なので幅は広く、
2〜8 万本・15〜70 GB）。1.5 秒間隔・`--workers 8` で 1 回目（1 自治体 400 本まで）が
2〜3 時間です。札幌市・堺市のように数千本ある自治体は、`--max-docs` を上げて個別に
回します（1 本 1.6 秒前後なので 2,600 本で 1.2 時間）。`review_required` 214 を足すと、
無作為 10 自治体の平均 13 本から 3 千本・2 GB 前後増えます。
